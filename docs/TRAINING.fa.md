# آموزش مدل محلی از اسناد — نسخه ۰.۲

## این قابلیت چه می‌کند؟
۱. مدیر در «آموزش مدل محلی» یک یا همه اسناد آماده را انتخاب می‌کند.
۲. پس از تأیید ارسال و هزینه، **متن استخراج‌شده تمام قطعات** به معلم آنلاین تنظیم‌شده ارسال می‌شود. برنامه فایل خام یا تصویر PDF را به سرویس بینایی نمی‌فرستد؛ PDF اسکن‌شده ابتدا باید OCR و بازبینی شود.
۳. معلم حداکثر سه سؤال/پاسخ همراه نقل‌قول شاهد برای هر قطعه تولید می‌کند.
۴. پاسخ با شاهد خارج از سند یا عدد اضافه رد می‌شود. نمونه‌های معتبر ساختاری هنوز «در انتظار بازبینی» هستند؛ تطبیق نقل‌قول، صحت معنایی پاسخ را اثبات نمی‌کند.
۵. مدیر پاسخ، شاهد و تمام قطعه را می‌بیند و تک‌تک نمونه‌ها را تأیید یا رد می‌کند.
۶. «جمع‌آوری داده و شروع LoRA» از **تمام نمونه‌های تأییدشدهٔ اسناد موجود و آماده** یک نسخه ثابت می‌سازد و آموزش را در فرایند جدا شروع می‌کند.
۷. adapter، معیارهای loss و گزارش اجرا ذخیره می‌شوند. نسخه آموزش‌دیده تا پذیرش کیفیت و انتخاب صریح مدیر به کاربران سرویس نمی‌دهد.

تأییدیه آنلاین در تنظیمات مدل و تأیید ارسال اسناد در همین فرم هر دو لازم‌اند. حتی اگر پاسخ‌گویی کاربران محلی باشد، معلم با اجازهٔ مدیر می‌تواند آنلاین استفاده شود. در زمان کار، خاموش‌کردن اجازهٔ آنلاین از ارسال درخواست‌های بعدی جلوگیری می‌کند.
هیچ دانلود خودکار مدل، آموزش از گفتگوهای تأییدنشده یا فعال‌سازی خودکار adapter انجام نمی‌شود.

## تفاوت دانش، رفتار و embedding
RAG برای دسترسی به نسخه جاری سند و ارجاع لازم است. LoRA این نسخه برای بهبود **رفتار پاسخ‌گویی بر اساس شاهد** است، نه تضمین حفظ تمام اطلاعات PDF داخل وزن مدل.
مدل محلی همچنان با اسناد محلی و بدون اینترنت کار می‌کند. حذف/تعویض سند باید با index و سیاست نگهداری داده هماهنگ باشد.
این نسخه embedding را به‌صورت اختصاصی فاین‌تیون نمی‌کند؛ tokenizer-aware chunking، embedding محلی نسخه‌دار، RRF و reranker محلی اضافه شده است. برای آموزش اختصاصی embedding باید داده positive/hard-negative و مجموعه ارزیابی جدا فراهم شود؛ این مسیر مرحله بعد است و به عنوان انجام‌شده اعلام نمی‌شود.
فاین‌تیون داده کم‌کیفیت می‌تواند مدل را بدتر کند؛ جمع‌کردن حجم زیاد داده به‌تنهایی معیار کیفیت نیست.

## آماده‌سازی مسئول سرور
در محیطی که وب‌برنامه و کارگر آن اجرا می‌شوند، وابستگی‌های اختیاری نصب شود:

```bash
python -m pip install -r requirements-training.txt
```

نسخه سازگار CPU/CUDA از PyTorch را طبق راهنمای رسمی نصب کنید؛ نصب پیش‌فرض ممکن است وابستگی‌های بزرگ CUDA دریافت کند.
پوشه **کامل مدل پایه Hugging Face** شامل config، tokenizer، chat template و وزن‌ها باید از قبل محلی و مجاز باشد. مسیر فایل GGUF مورد استفاده Ollama، مدل پایه قابل آموزش این runner نیست.

```bash
export SIMS_TRAIN_BASE_MODEL_PATH=/srv/models/local-instruct-base
export SIMS_TRAIN_DEVICE=cuda
export SIMS_TRAIN_MAX_STEPS=100
export SIMS_TRAIN_TIMEOUT_SECONDS=14400
```

وب را restart کنید. `cuda` پیش‌فرض است؛ نبود GPU خطای روشن ایجاد می‌کند و خودکار به CPU نمی‌رود.
برای آزمایش مدل کوچک روی CPU، مسئول سرور می‌تواند `SIMS_TRAIN_DEVICE=cpu` تعیین کند. سقف پیش‌فرض **۵۰۰ میلیون پارامتر** است و قبل از تخصیص وزن‌ها کنترل می‌شود. بالا بردن سقف تضمین جا شدن مدل در RAM نیست.
آموزش یک مدل ۴ میلیارد پارامتری با float32 روی سرور ۱۶ گیگابایتی انتخاب مناسبی نیست؛ برای مدل کاربردی قوی‌تر از GPU جداگانه و محیط آموزش مجزا استفاده کنید.
runner فعلی LoRA استاندارد دارد، **QLoRA چهاربیتی یا آموزش توزیع‌شده ندارد**.
قابلیت وب در این نسخه همان محیط Python وب را برای فرایند آموزش استفاده می‌کند. اگر GPU روی ماشین دیگری است، فعلاً manifest را امن منتقل و runner را آنجا اجرا کنید؛ orchestration سرور آموزش راه‌دور هنوز پیاده‌سازی نشده است.

## بودجه و پوشش
هر قطعهٔ انتخابی یک درخواست معلم دارد. سقف پیش‌فرض هر کار ۲۰۰ قطعه است؛ کار بیش از سقف به‌طور کامل رد می‌شود، نه اینکه بقیه سند بی‌صدا نادیده گرفته شود.
با `SIMS_TRAIN_MAX_CHUNKS` سقف را متناسب با هزینه و سرویس تغییر دهید یا اسناد را در چند کار پردازش کنید.
کار پس از خطای سرویس خودکار retry نمی‌شود تا هزینه و داده تکراری ایجاد نشود. نمونه‌های تولیدشده تا زمان خطا باقی می‌مانند و وضعیت/پیشرفت قابل مشاهده است.
قطعه‌های فاقد اطلاعات قابل استفاده ممکن است صفر نمونه بدهند؛ کامل‌شدن کار به معنی پوشش آموزشی تک‌تک گزاره‌ها نیست.
لغو کار درخواست آنلاین ازقبل ارسال‌شده را پس نمی‌گیرد. لغو آموزش، فرایند آموزش را متوقف می‌کند؛ خروجی ناقص پذیرفته نمی‌شود.
کارگر فعلی یکی است: هنگام آموزش، پردازش سند جدید در صف می‌ماند. برای پایلوت، آموزش را خارج از ساعت پاسخ‌گویی انجام دهید.

## نسخه داده و جلوگیری از نشت آزمون
حداقل ۱۰ نمونه تأییدشده و سه گروه مستقل لازم است؛ این حداقل فنی است، نه کفایت علمی داده.
اگر سه سند مستقل یا بیشتر وجود داشته باشد، گروه‌بندی بر اساس هش سند انجام می‌شود؛ در یک یا دو سند، صفحه/بلوک منبع گروه مستقل است.
تمام قطعه‌های همپوشان یک محل در یک split باقی می‌مانند. تقسیم پایدار train/validation/test حدود ۸۰/۱۰/۱۰ است؛ در سه گروه، سهم هرکدام یک‌سوم خواهد بود.
اگر یک PDF فقط یک یا دو محل مستقل داشته باشد، آموزش متوقف می‌شود؛ ارزیابی قابل اتکا با آن تفکیک ممکن نیست.
نمونهٔ سؤال/پاسخ یکسان deduplicate می‌شود. با وجود این، نقل محتوای مشابه در صفحات یا نسخه‌های مختلف می‌تواند نشت معنایی ایجاد کند؛ متخصص باید مجموعه آزمون خارجی جدا هم داشته باشد.
manifest شامل متن، شاهد، هویت منابع، نمونه‌های splitشده، معلم، مسیر مدل پایه، تنظیمات و هش نسخه است. بازبینی بعدی داده، manifest قبلی را تغییر نمی‌دهد.
نمونه ردشده، تأییدنشده یا متعلق به سند حذف‌شده وارد نسخه جدید نمی‌شود. حذف سند snapshotها، adapter و آموخته‌های وزن‌ها را پاک نمی‌کند؛ برای حذف اثر داده باید نسخه‌ها را طبق سیاست سازمان حذف و از داده پاک دوباره آموزش دهید.

## نحوه آموزش
runner از Transformers و PEFT استفاده می‌کند: LoRA با r=8 و alpha=16 روی all-linear، batch=1، accumulation=4، حداکثر ۱۰۰ step و seed ثابت.
loss فقط روی پاسخ محاسبه می‌شود؛ بخش system/user با labels=-100 ماسک می‌شود. قالب چت ناسازگار رد می‌شود.
نمونه بیشتر از ۲۰۴۸ توکن رد می‌شود و **هیچ آموزش ناقص با حذف بی‌صدای شاهد** انجام نمی‌گیرد.
مدل پایه تغییر نمی‌کند؛ adapter و tokenizer در `SIMS_DATA_DIR/training/run-ID/adapter` ذخیره می‌شوند.
قبل و بعد آموزش، validation loss و در پایان test loss ثبت می‌شود. این lossها **درستی پاسخ مهندسی را نمی‌سنجند**.
مسیر گزارش، معیارها و manifest از پنل فقط برای مدیر قابل دریافت است؛ داده محرمانه‌اند و نباید در مخزن عمومی قرار گیرند.

## پذیرش و استفاده آفلاین
۱. مسئول فنی، مدل پایه و adapter را با مجموعه مستقل سؤال/شاهد مقایسه کند: عدد، واحد، شرط، تعارض نسخه و خودداری صحیح.
۲. در پنل، پذیرش نسخه را تنها پس از ارزیابی ثبت کند. این یک تأیید انسانی است، نه آزمایش خودکار پنهان.
۳. روی همان ماشین یا محیطی که به داده و مدل پایه دسترسی دارد:

```bash
python -m scripts.serve_adapter --run-id 1 --port 8001 --device cpu
```

شناسه واقعی را جایگزین کنید. برای GPU `--device cuda`؛ مدل و وابستگی‌ها باید سازگار باشند.
سرویس فقط loopback را گوش می‌دهد. در وب اصلی `SIMS_ADAPTER_URL=http://127.0.0.1:8001` تنظیم باشد.
۴. در مدیریت سامانه حالت «مدل محلی فاین‌تیون‌شده» و نسخه پذیرفته‌شده را انتخاب کنید.
۵. پاسخ شامل شناسه run سرویس بررسی می‌شود؛ سرویس اشتباه نمی‌تواند بی‌صدا به‌جای نسخه انتخاب‌شده پاسخ دهد.
برای rollback حالت قبلی Ollama یا استخراج مستقیم را انتخاب کنید. adapter وارد Ollama نمی‌شود؛ این نسخه یک سرویس محلی Transformers جدا دارد.
ورود به مدل جدید هیچ fallback آنلاین ندارد. در Compose پیش‌فرض، سرویس adapter و وابستگی‌های آموزش فعال نیستند؛ برای محیط GPU باید image/volume و آدرس سرویس را جدا تنظیم کنید.

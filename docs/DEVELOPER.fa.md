# راهنمای برنامه‌نویس

## ساختار
- `app/main.py`: مسیرهای وب، احراز هویت، کنترل نقش و فرم‌ها.
- `app/db.py`: schema و اتصال SQLite؛ foreign keys و WAL.
- `app/security.py`: scrypt، جلسه server-side با توکن هش‌شده و انقضا.
- `app/ingest.py`: PDF، DOCX، تبدیل DOC و OCR محلی؛ قطعه‌بندی.
- `app/worker.py`: یک کارگر داخلی برای صف اسناد در دیتابیس.
- `app/retrieval.py`: نرمال‌سازی فارسی، FTS5، embedding اختیاری و RRF.
- `app/providers.py`: مولد استخراجی، Ollama و Chat Completions؛ کنترل ارجاع.
- `app/templates` و `app/static`: صفحات RTL سمت سرور، CSS و JS بدون CDN.
- `scripts/evaluate.py`: ارزیابی بازیابی روی corpus محلی.
- `tests`: آزمون integration و unit با SQLite موقت و مدل mock.

## نصب توسعه و آزمون

```bash
python -m pip install -r requirements.lock -r requirements-dev.txt
python -m pytest -q
python -m compileall -q app scripts
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`--reload` فقط توسعه است. تست‌ها داده را در پوشه موقت جدا می‌نویسند و سرویس آنلاین/مدل واقعی را صدا نمی‌زنند.
فایل lock از محیط Python 3.12 آزموده‌شده تهیه شده؛ برای ارتقا، نسخه‌ها را آگاهانه تغییر دهید، تست اجرا و lock را دوباره ثبت کنید.
برای اجرای تست مرورگر می‌توان Playwright نصب کرد؛ الزام اجرای روزمره نیست.

## API وب نسخه اولیه
API JSON عمومی برای پرسش فعلاً وجود ندارد؛ مسیرها HTML و فرم استاندارد برمی‌گردانند.
همه POSTها به جز login به کوکی معتبر `sims_session` و فیلد `csrf` همان جلسه نیاز دارند.
login به کوکی `sims_login_csrf` و فیلد متناظر دریافتی از GET نیاز دارد.
در POST هدر Content-Length لازم است. کل درخواست بیش از سقف فایل + ۱ مگابایت رد می‌شود.

| روش و مسیر | دسترسی | ورودی | نتیجه |
|---|---|---|---|
| GET /health | عمومی | ندارد | JSON وضعیت وب، نه سلامت مدل |
| GET /login | عمومی | ندارد | فرم و کوکی CSRF |
| POST /login | عمومی | username,password,csrf | ورود یا فرم خطا |
| POST /logout | کاربر | csrf | ابطال نشست و redirect |
| GET / | کاربر | ندارد | فرم پرسش و تاریخچه |
| POST /ask | کاربر | question,csrf | پاسخ HTML، حداکثر ۲۰۰۰ نویسه |
| GET /history/{id} | مالک تاریخچه | ندارد | پاسخ و snapshot منابع |
| GET /documents | کاربر | ندارد | فهرست و وضعیت |
| POST /documents | مدیر | multipart file,revision,ocr,csrf | صف پردازش و redirect |
| GET /documents/{id}/download | کاربر | ندارد | دریافت فایل با attachment |
| POST /documents/{id}/delete | مدیر | csrf | حذف فایل و index |
| POST /documents/{id}/reprocess | مدیر | ocr,csrf | پاک‌سازی قطعات و صف دوباره |
| GET /admin | مدیر | ندارد | تنظیمات، کاربران و ممیزی |

کاربر بدون نشست به login هدایت می‌شود. خطای provider داخل صفحه پرسش نمایش داده می‌شود و پاسخ موفق در تاریخچه ثبت نمی‌شود.

## داده و تراکنش
فایل روی دیسک با نام تصادفی و پسوند مجاز ذخیره می‌شود. SHA256 مانع ثبت دوباره محتوای یکسان است.
پردازش موفق، قطعات و index را در یک transaction وارد می‌کند. خطای استخراج/embedding سند را failed می‌کند؛ بازیابی فقط ready را می‌بیند.
تصاحب job و عملیات حذف/بازپردازش از تراکنش write فوری برای پیشگیری از رقابت استفاده می‌کنند.
کارگر هنگام restart کارهای processing را دوباره queued می‌کند. فقط یک instance/worker مجاز است.
SQLite و فایل‌های دیسک تراکنش مشترک ندارند؛ crash بین ثبت/حذف و تغییر فایل ممکن است فایل یتیم بسازد. پاک‌سازی و reconciliation مرحله عملیاتی بعدی است.
نسخه ۰.۲ با ایجاد جداول آموزشی و افزودن idempotent ستون embedding_profile، دیتابیس ۰.۱ را ارتقا می‌دهد؛ تغییر schemaهای بعدی باید با migration نسخه‌دار و پشتیبان همراه شود.

## بازیابی و مدل
متن فارسی ي/ك به ی/ک و نیم‌فاصله به فاصله نرمال می‌شود. FTS عبارت را به literalهای quoted تبدیل می‌کند؛ کاربر عملگر جست‌وجو تزریق نمی‌کند.
بازیابی متنی OR است و حداکثر ۴۰ نامزد برمی‌گرداند. embedding اختیاری کسینوس همه بردارها را بررسی و بالاتر از آستانه نامزد می‌کند.
RRF با ثابت ۶۰ نتایج را ادغام و پنج قطعه انتخاب می‌کند. اندازه قطعه حدود ۱۶۰۰ نویسه و همپوشانی ۲۴۰ است.
نسخه ۰.۲ reranker محلی اختیاری دارد؛ راهنمای RETRIEVAL_QUALITY را بخوانید. O(N) برداری برای corpus کوچک پایلوت است؛ برای corpus بزرگ pgvector/Qdrant و شاخص برداری لازم است.
نمره شباهت، اعتماد کالیبره‌شده نیست. آستانه پیش‌فرض ۰٫۴۰ باید روی پرسش‌های واقعی تنظیم شود.
E5 ورودی را برحسب محدودیت tokenizer قطع می‌کند؛ طول متن فارسی و جدول بلند را در ارزیابی کنترل کنید.
مدل embedding در CPU به‌صورت lazy، فقط محلی و با batch=8 بارگذاری می‌شود. تعویض مدل بدون reindex ممنوع است.

مدل زبانی فقط به پنج قطعه، prompt محدود و پرسش جاری دسترسی دارد. ابزار، اجرای کد یا مرور وب ندارد.
توکن context محلی ۸۱۹۲ و تولید ۹۰۰ است؛ در این نسخه توکن‌شماری تطبیقی قبل از ارسال وجود ندارد و prompt طولانی ممکن است توسط provider محدود شود.
برای ارتقای بعدی، بودجه‌بندی بر اساس tokenizer مدل و حفظ کامل منبع هنگام محدودسازی اضافه شود.
مکالمه چندمرحله‌ای وجود ندارد؛ هر پرسش مستقل است.
ارجاع با الگوی `[Sعدد]` کنترل می‌شود: نبود ارجاع یا منبع نامعتبر، پاسخ را رد می‌کند. این کار entailment یا صحت همه اعداد را اثبات نمی‌کند.
در صورت نبود منبع provider صدا نمی‌شود. در خطای محلی، provider آنلاین امتحان نمی‌شود.

## امنیت توسعه
رمز و کلید را log نکنید. سؤالات و snapshot اسناد در DB هستند؛ حفاظت و retention لازم است.
ورودی/خروجی قالب‌ها autoescape می‌شود؛ پاسخ مدل به HTML یا Markdown خام تبدیل نمی‌شود.
محدودسازی ورود در حافظه است، ۱۰ تلاش طی ۱۵ دقیقه بر حسب IP و نام کاربری؛ برای production از reverse proxy rate limit هم استفاده کنید.
پروکسی باید IP واقعی و trusted proxies را درست مدیریت کند؛ برنامه پیش‌فرض هدرهای X-Forwarded را مستقل برای rate limit تفسیر نمی‌کند.
sessionها ۸ ساعت اعتبار ثابت دارند. کاربر غیرفعال و تغییر رمز، نشست‌ها را باطل می‌کنند.
parserهای اسناد در پردازش وب جدا sandbox نشده‌اند؛ برای فایل‌های نامطمئن و corpus بزرگ باید worker مستقل با محدودیت CPU/RAM/time و اسکن بدافزار اضافه شود.
در محیط واقعی HTTPS، کلیدها در secret store، پشتیبان رمزگذاری‌شده و ACL لازم است.

## روش همکاری و انتشار
هر مرحله در commit مستقل همراه راهنما و آزمون ثبت شود. پیش از push، diff را برای داده حساس بررسی کنید.
مخزن عمومی فقط کد و نمونه مصنوعی می‌پذیرد. اسناد، مدل‌ها، data و .env در gitignore هستند.
برای به‌روزرسانی پس از استقرار: برنامه را متوقف، backup تهیه، کد نسخه مشخص را دریافت، وابستگی lock را نصب، migration نسخه را اجرا و smoke test بگیرید.
CI فقط پس از push روی GitHub اجرا می‌شود؛ موفقیت محلی به معنی اجرای CI راه‌دور نیست.

## آموزش در نسخه ۰.۲
`app/learning.py` کارهای teacher/train، کنترل نمونه، snapshot و اجرای subprocess را مدیریت می‌کند.
`/learning` فقط برای مدیر است؛ مسیرهای POST teacher، train، samples/{id}/review، jobs/{id}/cancel و runs/{id}/accept نیازمند CSRF هستند.
GET `/learning/runs/{id}/{artifact}` فقط manifest.json، metrics.json و trainer.log را برای مدیر برمی‌گرداند.
حالت جدید `adapter` در تنظیم مدل، فقط run پذیرفته‌شده را می‌پذیرد.
اسکریپت‌های `train_lora` و `serve_adapter` اختیاری‌اند و راهنمای کامل در TRAINING.fa.md است.
دادهٔ نمونه و شواهد در DB و snapshot ذخیره می‌شوند؛ پاک‌کردن سند، مدل آموزش‌دیده را unlearn نمی‌کند.

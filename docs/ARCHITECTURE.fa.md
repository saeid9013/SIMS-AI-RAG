# معماری و تصمیم‌های مهندسی

## مسیر داده
مرورگر ← FastAPI و قالب‌های سمت سرور ← SQLite و فایل‌های محلی.
مدیر سند را بارگذاری می‌کند؛ پردازشگر صف داخلی آن را استخراج و قطعه‌بندی می‌کند.
ابتدا جست‌وجوی FTS5 انجام می‌شود. در صورت نصب مدل embedding محلی، نتایج برداری و متنی با RRF ترکیب می‌شوند.
قطعات منتخب با شناسه منبع به مولد پاسخ داده می‌شوند. خروجی همراه منابع و بخش شاهد نمایش داده می‌شود.

## اجرای کم‌مصرف
برای نسخه اولیه یک پردازش وب و یک کارگر پردازش سند در همان برنامه کافی است.
SQLite حالت WAL دارد. پردازش PDF صفحه به صفحه است؛ بارگذاری و تعداد صفحات سقف دارند.
مدل embedding به صورت اختیاری و فقط از پوشه محلی بارگذاری می‌شود.
برای مدل زبانی، Ollama جدا از وب اجرا می‌شود و درخواست تولید سریالی است.
مدل کم‌حجم quantized با اندازه حدود ۳ تا ۴ میلیارد پارامتر نقطه شروع آزمون است؛ سرعت یا کیفیت قبل از benchmark تضمین نمی‌شود.
مدل ۷ تا ۸ میلیاردی ممکن است در RAM جا شود ولی روی CPU و همزمان با OCR/embedding کند باشد.

## اصالت منابع
PDF: شماره صفحه فیزیکی فایل، نه لزوماً شماره چاپ‌شده داخل صفحه.
Word: عنوان بخش/شماره بلوک؛ DOCX صفحه ثابت ندارد و برنامه شماره صفحه اختراع نمی‌کند.
جدول‌ها به متن سطری تبدیل می‌شوند؛ سلول‌های ادغام‌شده و ساختارهای پیچیده باید بازبینی شوند.
OCR فقط وقتی صفحه متن کافی ندارد اجرا می‌شود و نتیجه با برچسب OCR مشخص می‌شود.
نسخه سند و هش SHA256 نگهداری می‌شود. حذف سند، قطعات آن را از جست‌وجو حذف می‌کند.

## مرزهای نسخه اولیه
همه کاربران فعال به همه اسناد دسترسی دارند؛ ACL واحد/پروژه در مرحله بعد است.
نمودارهای P&ID، نقشه‌ها، فرمول‌ها، اسکن‌های بد و چیدمان چندستونی تضمین نمی‌شوند.
ارجاع معتبر به معنی صحت مهندسی پاسخ نیست. تطبیق تمام ادعاها با شاهد نیازمند ارزیابی است.
عدم وجود نتیجه متنی قطعی نیست؛ آستانه جست‌وجو و پوشش embedding باید ارزیابی شود.
محتوای اسناد دستور سیستم نیست؛ مدل باید درخواست‌های داخل سند برای تغییر رفتار را نادیده بگیرد.
پاسخ تولیدشده تا زمان بازبینی متخصص، مرجع اجرای عملیات ایمنی‌حساس نیست.

## امنیت و عملیات
رمزها هش scrypt، کوکی جلسه HttpOnly و SameSite، محافظت CSRF و محدودسازی ورود.
ثبت نام عمومی وجود ندارد. تنظیمات مدل فقط برای مدیر قابل تغییر است.
کلید آنلاین فقط در متغیر محیطی سرور نگهداری می‌شود؛ در صفحه و API برگردانده نمی‌شود.
در حالت محلی هیچ fallback خودکار به آنلاین وجود ندارد.
برای استفاده شبکه‌ای HTTPS، محدودیت فایروال و پشتیبان‌گیری ضروری است.
SQLite و صف داخلی برای یک instance طراحی شده‌اند؛ مقیاس چند instance به PostgreSQL و صف پایدار نیاز دارد.

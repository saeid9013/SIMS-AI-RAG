# ارزیابی کیفیت، کارایی و پذیرش پایلوت

## چه چیزی آزموده شده است؟
آزمون‌های خودکار از اسناد مصنوعی و provider شبیه‌سازی‌شده استفاده می‌کنند:
رمز و جلسه، نقش مدیر/کاربر، CSRF، استخراج ترتیب پاراگراف/جدول Word، شماره صفحه PDF، نرمال‌سازی فارسی، جست‌وجوی تگ، ذخیره تاریخچه، حذف از بازیابی، رد فایل/محتوای تکراری، محدودیت آنلاین، رد ارجاع نامعتبر و نبود fallback آنلاین.
این آزمون‌ها جای benchmark مدل واقعی، OCR واقعی و اسناد سازمان را نمی‌گیرند.
نتیجه اجرای فعلی در `docs/VALIDATION.md` ثبت می‌شود.

## مجموعه ارزیابی خصوصی
حداقل ۵۰ تا ۱۰۰ سؤال با نظر متخصص از اسناد مجاز تهیه کنید. برای هر سؤال پاسخ مرجع، سند/نسخه و محل دقیق شاهد را ثبت کنید.
شامل سؤال عدد/واحد، محدودیت عملیاتی، شرط/استثنا، جدول، فارسی روی متن انگلیسی، OCR، تگ مشابه، نسخه متعارض و سؤالی که پاسخ آن در corpus نیست باشد.
یک سند مصنوعی حاوی دستورهایی مثل «قوانین را نادیده بگیر» اضافه کنید و بررسی کنید این متن رفتار سیستم را عوض نکند.

فایل JSONL خصوصی برای ارزیابی بازیابی:

```json
{"question":"Design pressure of V-101?","expected_sources":[{"name":"V-101-Datasheet.pdf","location":"صفحه 2"}]}
```

نام و محل باید دقیقاً با کارت منابع برابر باشد؛ برای OCR پسوند ` · OCR` را هم وارد کنید.
پس از ورود اسناد:

```bash
python -m scripts.evaluate /private/evaluation.jsonl --k 5 > /private/retrieval-report.json
```

این دستور فقط بازیابی را می‌سنجد، مدل زبانی را اجرا نمی‌کند و گزارشش ممکن است نام اسناد و سؤال‌های محرمانه داشته باشد؛ آن را commit نکنید.

## شاخص‌ها
| شاخص | روش |
|---|---|
| Mean Recall@5 | میانگین سهم محل‌های شاهد صحیح در پنج قطعه اول؛ توسط اسکریپت |
| صحت پاسخ | بررسی متخصص برای ادعا، عدد، واحد، شرط و هشدار |
| صحت ارجاع | آیا هر ادعا واقعاً در همان شاهد آمده، نه صرفاً وجود شناسه؟ |
| خودداری درست | در نبود پاسخ، آیا مدل صریحاً عدم کفایت شواهد را گفته؟ |
| استخراج | مقایسه متن خوانده‌شده با اصل، خصوصاً جدول و اعشار OCR |
| تعارض نسخه | آیا اختلاف به کاربر اعلام شده و از تلفیق ناموجه خودداری شده؟ |
| زمان | زمان پایان‌به‌پایان پرسش، صدک ۵۰ و ۹۵، سرد و گرم |
| RAM | RSS وب، Ollama و OCR همزمان و peak سیستم |
| آفلاین | تکرار login/upload/search/local-answer با قطع خروج شبکه |

## طرح آزمون روی سرور ۱۶ گیگابایتی
۱. ابتدا lexical + extractive را با ۱۰ سند کنترل کنید.
۲. embedding محلی را فعال، اسناد را بازپردازش و Recall را مقایسه کنید.
۳. مدل کم‌حجم محلی را روی همان سؤال‌ها اجرا کنید؛ صحت و زمان را ثبت کنید.
۴. هنگام پاسخ، یک سند اسکن‌شده پردازش کنید و RAM/زمان را بسنجید.
۵. دو کاربر همزمان سؤال بپرسند؛ رفتار «مدل مشغول» و قابلیت استفاده صفحات را کنترل کنید.
۶. سرویس و سپس سرور را restart و بازیابی job/جلسه/فایل را کنترل کنید.
۷. خروج اینترنت را مسدود کنید؛ هیچ بخش رابط نباید به CDN، فونت اینترنتی یا مدل دانلودنشده نیاز داشته باشد.

## معیار پذیرش
آستانه‌ها باید توسط مالک فنی سازمان و تیم بهره‌برداری تعیین شوند؛ پروژه هنوز امتیاز کیفیت اندازه‌گیری‌شده روی داده واقعی ندارد.
برای سؤال‌های حساس، ادعای بدون شاهد یا عدد اشتباه باید مانع پذیرش پایلوت شود؛ میانگین خوب خطای بحرانی را جبران نمی‌کند.
اگر بازیابی ضعیف است parser/chunking/embedding/reranker را اصلاح کنید. اگر شواهد درست ولی جواب غلط است prompt/مدل و کنترل ادعا را بهبود دهید.
فاین‌تیون فقط پس از تفکیک این خطاها، داشتن داده مجاز و آزمون مستقل بررسی شود؛ برای یادگیری اسناد جدید معمولاً reindex نخستین اقدام است.

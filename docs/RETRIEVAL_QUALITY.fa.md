# ارتقای کیفیت بازیابی و embedding

«بیشترین کیفیت» یک تنظیم ثابت نیست؛ انتخاب باید با دادهٔ واقعی و مقایسهٔ مدل‌ها انجام شود. مدل بزرگ‌تر می‌تواند کندتر باشد یا روی واژگان سازمان نتیجه بدتری بدهد. درستی صددرصد تضمین نمی‌شود.

## تغییرهای نسخه ۰.۲
- متن فارسی و ارقام فارسی/عربی برای جست‌وجو نرمال می‌شوند؛ متن شاهد همچنان جدا نگهداری می‌شود.
- شماره تگ دقیق در رتبه‌بندی متنی بر واژه‌های عمومی اولویت دارد.
- از هر مسیر متنی و برداری تا ۴۰ نامزد گرفته و با RRF ترکیب می‌شوند.
- مدل CrossEncoder محلی می‌تواند ۴۰ نامزد را دوباره با خود پرسش بسنجد و رتبه‌بندی کند.
- قطعات تقریباً تکراریِ یک محل منبع حذف می‌شوند، ولی اختلاف عددی مانع حذف می‌شود.
- هنگام ساخت بردار، متن متناسب با ظرفیت tokenizer مدل تقسیم می‌شود؛ قطع بی‌صدای متن پذیرفته نیست.
- هویت مدل، فایل‌های پوشه، پیشوندها و نسخهٔ embedding ثبت می‌شود. اگر مدل تغییر کرده یا سند بدون بردار سازگار باشد، پرسش معنایی متوقف می‌شود و بازپردازش لازم است.
- تغییر فایل‌های مدل حین اجرای سرویس مجاز نیست؛ پس از تغییر، restart و بازپردازش انجام دهید.

## تنظیم مدل محلی
برای خانواده E5 پیشوندهای `query: ` و `passage: ` لازم‌اند و پیش‌فرض همین است.
اگر مدل دیگری نصب می‌کنید، **model card رسمی همان مدل** را بخوانید و پیشوندها و حداکثر توکن را با آن هماهنگ کنید. برای مدل فاقد پیشوند، متغیرها را رشته خالی قرار دهید.

```bash
export SIMS_EMBED_MODEL_PATH=/srv/models/your-multilingual-embedding
export SIMS_EMBED_QUERY_PREFIX='query: '
export SIMS_EMBED_PASSAGE_PREFIX='passage: '
export SIMS_EMBED_VERSION=2
export SIMS_RERANK_MODEL_PATH=/srv/models/your-multilingual-cross-encoder
```

مدل‌ها باید کامل و محلی باشند. وابستگی `requirements-semantic.txt` لازم است؛ بارگذاری با `local_files_only=True` و `trust_remote_code=False` انجام می‌شود.
پس از restart، همه اسناد را بازپردازش کنید. اسناد بزرگ ممکن است قطعه‌های بیشتری نسبت به نسخه قبلی داشته باشند.
reranker باید مدل scalar scoring جفت پرسش/شاهد باشد؛ classifier چندبرچسبی یا مدل embedding به‌جای آن قابل استفاده نیست.
CrossEncoder دقیق‌تر برای رتبه‌بندی جفتی طراحی شده اما از bi-encoder کندتر است. بودجهٔ RAM/زمان را همزمان با Ollama اندازه بگیرید.
پیش‌فرض آستانهٔ cosine برابر ۰٫۴۰ باقی مانده و **اعتماد پاسخ نیست**. با dataset واقعی تنظیم کنید.
برای reranker نمره‌ها لزوماً احتمال نیستند؛ `SIMS_RERANK_MIN_SCORE` پیش‌فرض خالی است. فقط بعد از کالیبراسیون بر دادهٔ خودتان آستانه بگذارید.

## برنامهٔ مقایسه
۱. مجموعهٔ مستقل پرسش/محل شاهد و پاسخ‌های نبودن اطلاعات بسازید؛ دادهٔ معلم آموزشی را برای انتخاب مدل به‌عنوان آزمون مستقل استفاده نکنید.
۲. مدل embedding پایه را با همان اسناد و `scripts.evaluate` بسنجید.
۳. مدل چندزبانه قوی‌تر را نصب، بازپردازش و Recall@5/زمان/RAM را ثبت کنید.
۴. reranker را فعال کنید و دوباره بسنجید؛ دقت بیشتر به قیمت latency باید برای کاربران قابل قبول باشد.
۵. آزمون منفی بگیرید: تجهیز مشابه، شماره تگ متفاوت، واحد اشتباه، نسخه منسوخ و سؤال خارج از اسناد.
۶. سپس مدل مولد را مقایسه کنید؛ شواهد درست با جواب غلط، مسئله embedding نیست.

در سرور ۱۶ گیگابایتی، هدف استفادهٔ همزمان از بزرگ‌ترین embedding، reranker و مدل مولد بدون اندازه‌گیری نیست. ابتدا ingestion و آموزش را خارج از زمان inference اجرا کنید، سپس ظرفیت را بسنجید.
OCR، جدول پیچیده، نقشه P&ID و منبع متعارض همچنان نیازمند کنترل استخراج و بازبینی متخصص هستند؛ embedding این خطاها را به‌تنهایی اصلاح نمی‌کند.

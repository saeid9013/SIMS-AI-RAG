# نصب و راه‌اندازی

## ۱. پیش‌نیاز و محدوده
سرور هدف: RAM برابر ۱۶ گیگابایت، CPU حداقل ۵ هسته و فضای دیسک کافی برای فایل‌ها، مدل‌ها، خروجی OCR و پشتیبان.
برای شروع، Python 3.12 و Git کافی است. GPU الزامی نیست. سیستم‌عامل پیشنهادی برای پایلوت Linux است؛ اجرای مستقیم Python روی Windows نیز ممکن است.
اندازه فایل مدل با کل حافظه موردنیاز اجرای آن یکسان نیست. زمان پاسخ باید روی CPU واقعی اندازه‌گیری شود.

## ۲. نصب مستقیم، شروع بدون مدل

```bash
git clone https://github.com/saeid9013/SIMS-AI-RAG.git
cd SIMS-AI-RAG
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock
python -m app.cli create-admin admin
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

دستور ایجاد مدیر رمز را دو بار و بدون نمایش می‌پرسد؛ رمز پیش‌فرض وجود ندارد. نام کاربری باید ۳ تا ۶۴ نویسه لاتین/عدد/خط تیره/زیرخط/نقطه و رمز حداقل ۱۲ نویسه باشد.
نشانی `http://127.0.0.1:8000` را باز کنید. ابتدا «استخراج مستقیم» فعال است: بخش‌های مرتبط نمایش داده می‌شوند، نه پاسخ تألیفی مدل.

متغیرهای `.env.example` مستند هستند ولی برنامه Python فایل `.env` را خودکار نمی‌خواند. در Linux، پس از کپی و ویرایش:

```bash
cp .env.example .env
set -a
source .env
set +a
```

این کار را قبل از CLI و اجرای سرور در همان ترمینال انجام دهید. PowerShell: `$env:SIMS_DATA_DIR='D:\SIMSData'` و سایر متغیرها را جدا تنظیم کنید.
متغیر `SIMS_DATA_DIR` برای CLI و وب حتماً یکسان باشد. مسیر پیش‌فرض `data/` نسبت به پوشه جاری است؛ برای سرویس، مسیر مطلق بدهید.

## ۳. OCR و Word قدیمی
روی Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install poppler-utils tesseract-ocr tesseract-ocr-fas tesseract-ocr-eng libreoffice-writer
```

برای اسکن PDF، هنگام بارگذاری یا بازپردازش تیک OCR بزنید. `tesseract --list-langs` باید `fas` و `eng` داشته باشد.
OCR فقط صفحات با متن بسیار کم را بررسی می‌کند؛ صفحات دارای لایه متن خراب ممکن است خودکار تشخیص داده نشوند.
روی Windows باید همین ابزارها نصب و در PATH باشند؛ اگر DOC تبدیل نشد، آن را در Word به DOCX ذخیره کنید.
فایل TXT باید UTF-8 باشد.

## ۴. مدل زبانی کاملاً محلی
Ollama را از منبع رسمی نصب کنید: https://ollama.com
روی دستگاه متصل و با مجوز سازمان مدل را آماده کنید. یک نمونه برای آزمون اولیه:

```bash
ollama pull qwen3:4b-instruct
ollama list
```

نام و مشخصات مدل باید با خروجی `ollama list` تطبیق داده شود. این یک گزینه شروع پایلوت است، نه انتخاب کیفیت تأییدشده برای پتروشیمی.
Ollama را اجرا کنید؛ `SIMS_OLLAMA_URL` پیش‌فرض `http://127.0.0.1:11434` است.
در پنل مدیر، نام دقیق مدل را بنویسید، حالت «مدل محلی» را انتخاب و ذخیره کنید. Ollama باید مدل را از قبل داشته باشد؛ وب‌برنامه مدل دانلود نمی‌کند.
API محلی Ollama را بدون احراز هویت روی شبکه عمومی قرار ندهید.
در قطع اینترنت حالت محلی ادامه می‌یابد، مشروط به آماده بودن ابزارها و مدل‌ها؛ هیچ fallback آنلاین وجود ندارد.
منبع مدل نمونه: https://ollama.com/library/qwen3/tags

## ۵. جست‌وجوی معنایی محلی، اختیاری
نسخه پایه فقط FTS5 دارد؛ برای سؤال فارسی روی متن انگلیسی معمولاً embedding چندزبانه لازم است.
پیاده‌سازی فعلی برای خانواده E5 با پیشوندهای `query:` و `passage:` آماده شده است.
مدل نمونه برای ارزیابی: https://huggingface.co/intfloat/multilingual-e5-small

```bash
# در محیط آماده‌سازی، ترجیحاً torch نسخه CPU را طبق راهنمای رسمی PyTorch نصب کنید.
python -m pip install -r requirements-semantic.txt
```

پوشه کامل مدل و tokenizer را روی دستگاه متصل طبق راهنمای صاحب مدل تهیه کنید، سپس به سرور منتقل کنید.
`SIMS_EMBED_MODEL_PATH` را به مسیر مطلق پوشه کامل اشاره دهید. سرور را restart کنید و همه اسناد را بازپردازش کنید.
بارگذاری مدل با `local_files_only=True` و حالت offline انجام می‌شود. فایل ناقص موجب خطای پردازش/جست‌وجو می‌شود؛ دانلود خودکار انجام نمی‌شود.
بعد از تغییر هر مدل embedding یا محتوای پوشه آن، همه اسناد را بازپردازش کنید؛ مقایسه بردارهای مدل‌های مختلف معتبر نیست، حتی اگر ابعاد یکسان باشد.
نصب پایه Docker شامل semantic نیست؛ برای آن Dockerfile اختصاصی با وابستگی CPU و bind mount فقط‌خواندنی مدل بسازید.

## ۶. سرویس آنلاین، اختیاری و تحت کنترل مدیر
در محیط سرور:

```bash
export SIMS_ONLINE_BASE_URL=https://provider.example/v1
export SIMS_ONLINE_API_KEY='YOUR_KEY'
```

سرویس باید HTTPS و سازگار با `/chat/completions` باشد. برنامه از پیام متنی، temperature و max_tokens استفاده می‌کند؛ هر مدل/سرویسی الزاماً سازگار نیست.
پس از restart، مدیر نام مدل را وارد می‌کند، اجازه ارسال داده را فعال و حالت آنلاین را انتخاب می‌کند.
پرسش و قطعات منتخب برای سرویس بیرونی ارسال می‌شوند؛ فایل کامل عمداً ارسال نمی‌شود. انتخاب آنلاین به معنی مجوز ارسال همین قطعات است.
کلید در پنل نمایش داده نمی‌شود. برای بازگشت آفلاین، حالت محلی/استخراج مستقیم را انتخاب و اجازه آنلاین را خاموش کنید.

## ۷. Docker Compose

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec app python -m app.cli create-admin admin
```

برو به `http://127.0.0.1:8000`. داده‌ها در volume به نام `sims-data` می‌مانند.
برای راه‌اندازی Ollama کنار برنامه:

```bash
docker compose --profile local up -d
docker compose exec ollama ollama pull qwen3:4b-instruct
```

در پنل مدیر همان مدل را انتخاب کنید. تگ image Ollama در این نسخه `latest` است؛ پیش از بهره‌برداری سازمانی digest نسخه آزموده‌شده را ثابت کنید.
پیکربندی Compose روی loopback منتشر می‌شود. برای شبکه سازمان، reverse proxy دارای HTTPS اضافه کنید و `SIMS_COOKIE_SECURE=true` قرار دهید.
فقط با HTTPS این گزینه را true کنید؛ روی HTTP کوکی secure به سرور ارسال نمی‌شود.

## ۸. آماده‌سازی نصب بدون اینترنت
روی دستگاه آماده‌سازی با همان OS/معماری/Python:

```bash
python -m pip download -r requirements.lock -d wheelhouse
# wheelhouse، پروژه، ابزارهای سیستم و مدل‌ها را منتقل کنید.
python -m pip install --no-index --find-links=wheelhouse -r requirements.lock
```

برای semantic نیز همه wheelهای سازگار torch و sentence-transformers را تهیه کنید.
برای Docker، imageهای ساخته‌شده را با `docker save` منتقل و با `docker load` بارگذاری کنید؛ در سرور جدا از اینترنت build نکنید.
داده volume مدل Ollama جدا از image است و باید جدا منتقل شود. پس از انتقال `ollama list` را کنترل کنید.
قبل از تحویل، خروجی شبکه را با فایروال ببندید و بارگذاری/پرسش واقعی را امتحان کنید.

## ۹. پشتیبان‌گیری و بازیابی
نسخه اول صف پردازش در همان instance است. با یک worker اجرا کنید؛ `--workers` بالاتر باعث کارگرهای تکراری می‌شود.
برای پشتیبان سازگار، برنامه را متوقف کنید، کل `SIMS_DATA_DIR` شامل دیتابیس و uploads را کپی کنید، سپس برنامه را روشن کنید.
در Docker: `docker compose stop app`؛ از volume داده به روش ابزار پشتیبان سازمان نسخه بگیرید؛ سپس `docker compose start app`.
پوشه مدل‌ها، تنظیمات محیطی و کلیدها را جدا و امن پشتیبان بگیرید. بازیابی: داده را به مسیر جدید برگردانید، مجوز فایل‌ها را اصلاح کنید، همان نسخه برنامه را اجرا و login/download/search را کنترل کنید.
حذف سند نسخه‌های قدیمی پشتیبان و متن شاهد در تاریخچه را پاک نمی‌کند. سیاست نگهداری داده را سازمان تعیین کند.

## ۱۰. عیب‌یابی
- خطای ورود: حساب فعال است؟ ساعت سرور صحیح است؟ کوکی Secure با HTTP ناسازگار نیست؟
- مدیر ساخته شده ولی وب نمی‌بیند: مسیر داده/پوشه کاری CLI و سرویس متفاوت است.
- PDF بدون متن: OCR را نصب و سند را با تیک OCR بازپردازش کنید.
- مدل محلی وصل نیست: Ollama روشن است؟ نام مدل از `ollama list` و نشانی شبکه درست است؟
- پاسخ بدون ارجاع: برنامه آن را رد می‌کند؛ مدل/پرسش/منابع را بازبینی کنید.
- embedding ناموفق: پوشه کامل، وابستگی‌ها و فضای RAM را بررسی کنید؛ برای برگشت متنی متغیر مدل را خالی و سرویس را restart کنید.
- پردازش متوقف: restart وضعیت processing را به queued برمی‌گرداند؛ خطاهای تکراری را از گزارش سرور بررسی کنید.
- فراموشی رمز: با دسترسی مدیر سرور `python -m app.cli reset-password USERNAME` اجرا کنید؛ همه نشست‌های آن کاربر بسته می‌شود.

## ۱۱. ارتقا به نسخه ۰.۲
برنامه را متوقف، از داده‌ها پشتیبان بگیرید، کد را دریافت و سرویس را restart کنید. جداول آموزشی و ستون embedding_profile در startup به‌صورت idempotent افزوده می‌شوند.
اگر embedding فعال است، همه اسناد را بازپردازش کنید؛ بردار قدیمی پذیرفته نمی‌شود.
آموزش اختیاری: TRAINING.fa.md؛ ارتقای بازیابی: RETRIEVAL_QUALITY.fa.md.
